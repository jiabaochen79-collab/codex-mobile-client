# 0.4.53 纯手写提问卡片兼容性修复

日期：2026-10-12。

## 问题与修复

0.4.52 原生卡片定位逐字比较问题原文与桌面控件文字。但桌面显示会去掉 Markdown 格式，整理换行和多余空格，导致带格式的问题无法定位。纯手写问题还使用不同的输入框布局，原来的三层父节点查找范围不足。

本版本将普通 Markdown 问题转换为显示文字，并在原生层统一空白和实体文字比较。定位支持较深的纯手写卡片，查找止于当前任务文档；仍拒绝多输入框、多提交按钮或任务标题、进程身份不一致的情况。提交后也只核对目标任务中的未回答卡片。

窗口不可用、定位失败、输入框不支持填写、已有不同草稿和提交按钮不可用分别返回具体提示。读取输入框失败不再误报草稿冲突。原问题标识和正文的提交后验证、授权复核及结果不确定时不重发的规则保留。

本次不修改服务器实现、手机界面、通信协议、支付或订阅。服务器交付只需发布新版 Windows 安装包。

## 已验证

- 新增接口回归先失败后通过，覆盖带格式和换行的中文纯手写问题及分类错误提示。
- 原生 UIA 测试覆盖浅层卡片、深层纯手写布局、多输入框、问题不匹配、标题不匹配、任务文档隔离和提交结束判断。
- 本机独立真实任务提出没有预设选项、含 Markdown 和换行的中文问题；使用手机格式回答，原生卡片关闭，答案在正确问题历史中仅出现一次，模型确认收到答案。
- 552 项单元及原生测试、105 项组件测试通过。
- Chromium 和 WebKit 各 5 项相关手机交互测试通过，覆盖提问隔离、整批和手写提交、聊天草稿保留及拒绝后重试。
- 类型检查、原生编译和生产构建通过。
- 公开仓库历史扫描通过，没有服务器路径或已知凭据模式。

真实任务使用独立兼容性测试数据，没有重放截图中的业务回答。截图涉及的公司电脑实际窗口状态和原始问题尚未直接读取，iPhone/Android 真机提交仍需独立验收；不能据本机结果断言所有窗口或任意 HTML 问题已兼容。
