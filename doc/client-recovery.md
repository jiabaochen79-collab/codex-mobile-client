# 客户端恢复

Windows 助手监测同一 Windows 用户和会话中的 Codex 主进程。只在确认主进程异常退出后自动打开客户端；网络断线、接口超时、正常关闭及 Windows 注销不会触发自动启动。助手需保持运行，并开启远控。

## 使用入口

- 手机：聊天或首页的“更多”→“客户端恢复”。查看模式下先接管控制权；电脑助手离线时无法远程启动。
- Windows：助手“帮助”→“客户端恢复”。可手动恢复或暂停自动恢复。

异常退出后按 3、15、45 秒退避，最多尝试三次；状态检测周期会让实际启动略晚于退避时间。打开客户端后需通过本机连接和兼容检查才显示恢复成功。连续失败后停止尝试，可核对原因并手动恢复。连续健康运行五分钟才重置自动尝试次数；开关自动恢复不会清除次数。

恢复只负责打开客户端和恢复连接，不自动执行中断任务、不自动继续已暂停的队列，也不重发结果不明的消息。手机会保留当前任务、草稿、附件及已有内容。恢复后先核对执行结果，再选择继续任务或队列。

管理员封禁、关闭远控、暂停恢复、助手升级或助手退出会取消后续自动启动。远程手动恢复沿用订阅和控制权检查。设备封禁状态在助手断线和重启后仍保留，直到服务器明确解除。

## 退出记录

面板显示最近退出时间、Codex 版本、退出原因和退出码。助手数据目录的 `logs/desktop-recovery.jsonl` 仅记录退出和恢复状态，最多保留当前及上一份约 1 MiB 日志；可用时附带匹配的 Windows Application Error 模块名和异常码，不记录聊天正文、密码或文件内容。

反馈诊断只会增加 `DESKTOP_EXIT_<退出码>`，不会自动上传完整日志或模块路径。恢复机制用于降低闪退后的人工处理成本，不能据此认定 Codex 本身的闪退原因已修复。
